# SkillFlow 1.5.85

Tools can raise the public `skillflow.ToolExecutionRefused` exception when a
known deterministic validation or constraint definitively refuses an invocation.
Normal inline tool-node dispatch fails the step and run with the original
reason, without automatic retry, confirmation, or downstream routing. Use this
type only where retrying the same invocation cannot help; transient I/O,
incomplete external effects, and unknown failures retain ordinary retry behavior.

If cancellation already requested a stop while the tool was admitted, the
refusal remains on the failed step and the existing operation retirement settles
the run with its original stop reason. No second cancellation mechanism is added.

This release preserves the previously accepted 1.5.84 cancellation correction.
