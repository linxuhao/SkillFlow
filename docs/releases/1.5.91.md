# SkillFlow 1.5.91 — Source candidate

Both core validation callsites supply the already-known claim run/step and
resolver code root to StepValidator. Its copied per-instance tool_context
replaces identity fields from validation specs, forwarding only callable-
supported keywords. Without context those fields are empty, including an empty
root for repo-less runs. Native lint carries the same optional explicit fields
into host backends, while Path-only and opaque legacy backends retain their
existing convention. No global context, path-inferred owner, run creation or
runtime/DB interface is introduced. Host backends remain responsible for actual
ownership checks and isolated execution.

The first unpublished context candidate80c5e73 failed independent review: a
Path-only backend's first parameter could legitimately be named project_root,
run_id or step_id. Forwarding an extra keyword with that name double-bound it
and silently sacrificed name independence. Six unchanged observed regression
cases (valid and invalid syntax for each spelling) now remain in the SDK tests.
Native lint derives consumed parameters by binding the actual positional Path
against the full callable signature. It forwards remaining supported context;
positional-only and variadic parameters retain normal Python binding rules.
Original failed Source/wheel and independent evidence remain immutable. This
correction does not rename the public convention or relax its requirement.
