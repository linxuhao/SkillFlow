# SkillFlow 1.5.96 — checkpoint revision retry cursor

A retryable executor or confirmation failure keeps the failed producer as the
run's current node. A rejected checkpoint revision therefore reclaims its own
pending execution instead of routing from the older completed checkpoint and
publishing its stale approval identity again.

Required fixed-slot capture still refuses incomplete output. A complete valid
retry must finish before a new checkpoint becomes available. Completed history,
retry accounting, completion ordering and stale/colliding approval refusals are
unchanged. Exact committed decisions remain safe to replay.

The implementation is the accepted Source commit
`3abdfff9896a646fe9df814d9eca74f78588fa34`; this release preparation changes only
version metadata and release documentation. It does not publish a package,
install a backend, recover a production run or certify DPE delivery.
