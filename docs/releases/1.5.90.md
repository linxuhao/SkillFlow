# SkillFlow 1.5.90

Code-target write/create/edit tools and native apply_patch (Add/Update/reference
operations) refuse a Git-ignored destination before any filesystem, journal,
echo or output-ownership mutation. The refusal names the ignore source, line and
pattern, so a corrected filename can be delivered in the same claim. Tracked
files that match an ignore rule and negated patterns stay writable; artifact
targets and declared artifact appends are unaffected. Official 1.5.89 instead
accepted the write, created the file and failed only at step finalization.

Package Source is accepted Source 89d16f4117a27c875bd8e7fb6b444c5e6f59671f
(parent: official v1.5.89, 48e2ae649b6c5373fea2cfa2703aee35c4d07e96) plus this
note, version metadata and one test-oracle reconciliation. Runtime, refusal and
multi-edit semantics are not changed by those additions.

The sweep oracle in tests/test_the_journal_records_what_the_applier_wrote.py
predates accepted Source 1929838, which refuses an older insertion-point
citation once an earlier deletion consumed its immediate left neighbor
(docs/cited-point-history.md). The oracle still expected such a point just after
a deleted line to land at its shifted position; those 21 cases failed identically
on official 1.5.89. Its expectation now refuses that point too; refusals continue
to assert the file is byte-unchanged. No test was deleted, skipped or xfailed.
