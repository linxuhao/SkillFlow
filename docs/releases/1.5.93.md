# SkillFlow 1.5.93 — Runner protocol fixes and pipeline overview

Base: published 1.5.92 Source 976fc117ba7bb81bc62e2ce74c423107593082dc.

Runner mode (skillflow-run / skillflow-mcp / RunnerService) for external agents:

- `skillflow-run --action submit` now stages every result slot into its
  declared output file before confirming, through the same
  `RunnerService.submit` the MCP transport uses. Before, the CLI recorded the
  dict only as step outputs: validated steps failed with "File not found",
  the next step's context lacked the submitted text, and `skillflow-convert`
  could not get past its first step. `--step-id` defaults to the current step;
  a mismatching one reports the step that is actually waiting.
- A slot value the write tool refuses (e.g. invalid JSON for a `.json` slot)
  returns `validation_error` naming the slot on the same step instead of
  raising through the transport.
- Every runner instruction opens with `## Pipeline overview`: all steps in
  graph order with type, human checkpoints, outgoing conditions and loop
  bounds, the current step marked, completion counts and position. Built from
  the graph version the run is pinned to; windowed around the current step for
  graphs over 30 steps. Routing is unchanged — the engine still decides.
- The `mcp` extra is pinned to `mcp>=1.2,<2`. mcp 2.x removed FastMCP, so a
  fresh `pip install skillflow-py[mcp]` installed a server that crashed on
  import.
- `skillflow-mcp --graphs <dir>` skips the `--agent-configs` file when it sits
  in that directory (the README layout) instead of loading it as a graph.

Docs: README "Runner Mode", skill_runner AGENT.md. Tests:
src/skillflow/plugins/skill_runner/tests/test_cli_submit.py, test_overview.py.
