# 终态写作

**一句话**：交付物写它**现在是什么样**，不写它**相对上一版变成了什么样**。

读你产物的人没看过上一版，也没看过让你改的那份反馈。凡是只有"看过上一版的人"才读得懂的句子，都不属于终态。

**自检问句**：读者手上只有这一份文件，这句话还成立吗？还有意义吗？
不成立 → 删；成立但需要上一版做参照才通顺 → 改写成绝对陈述。

---

## 三种违规

### 1. 相对上一版的叙述（文档、README、prompt、注释）

| ✗ | ✓ |
|---|---|
| `现在改成了按 owner 判活` | `按 owner 判活：活着的 owner 永不回收` |
| `新增了 scope 字段` | `scope=task\|all 决定循环体产物的读取范围` |
| `不再需要手动 bump 版本` | `版本由发布脚本写入` |
| `（已修复）零字节写入` | `零字节写入报失败` |
| `V2 里 promotion 改成了整目录替换` | `promotion 整目录替换` |

变更史归 git。`git log` 里有的东西在文档里再写一遍，只会随着下一次改动过期成谎话——而没人会回头删它。

### 2. 过程残留 / 元叙述（正文、代码、任何交付文件）

`（此处未改动）`、`以下是修改后的版本`、`已按反馈修改如下`、`[说明]`、`TODO`、占位内容、`<!-- 原文 -->`。

宿主 AItelier 的机检直接拦这一类：`AItelier/aitelier/novel_state.py` 的
`META_MARKERS = ["[说明]", "TODO", "（待补充）", "（此处", "[待", "<!--"]`，
`continuity_check` 命中即硬失败、打回重做。

元叙述属于**你的回话**，不属于**产物**。要说明改了什么，写在对话、commit message 或 PR 描述里。

### 3. 增量代替终值

- 状态/记账/配置写终值：`power_level: 500`，不是 `+490`（AItelier `templates/novel_finalize.md` 第 2 条）。
- 返工产物交完整文件，不交补丁、不交 diff、不"只贴改动的那几段"。

## 返工时怎么做到终态

被评审/机检/用户打回后重交，只有两条路，**都不是补丁**：

1. **外科 edit**（有上一版做基线时的首选）
   `edit(old_str=<被点名的原文>, new_str=<改后>)` 只动被点名处，没点名的部分逐字带过。
   物理上不可能把上一轮已经改好的地方改回去——这是它比重写强的唯一理由，也是全部理由。

2. **全量 write**
   把完整终态一次写全，没改动的部分原样照抄。凭记忆复原全文会静默弄坏没被投诉的段落，所以只在"推倒重来"时用。

**不存在的第三条路：只写这轮改动的那部分。**
本库的提升是 `shutil.rmtree(step_dir)` + `os.rename(tmp_dir, step_dir)`（`src/skillflow/core.py`，`_step_commit`）：**本轮没写进 staging 的文件，提升后就不在 `{step}/` 里了**（staging 完全为空是唯一例外：提升整个不发生，上一版原样留着——但只要你写了任何一个文件，整目录就被替换）。多产物步骤尤其致命——只重写了 `pipeline.yaml`，`role_table.yaml` 就此消失，步骤以 "File not found" 失败。判例见 AItelier `templates/forge_emit.md` 的
"Your output directory starts EMPTY on every attempt, and REPLACES the last one"。

## 例外（别过度应用）

- **commit message / PR 描述 / CHANGELOG / release notes**：读者要的就是变更，写变更。
  但**正文仍按终态判据写**——描述行为现在是什么样，不是"我动了哪几行"：
  `fix(file_exists): a 0-byte file is the wrote-nothing case wearing a file`。

- **事故判例（ledger）**：CLAUDE.md 里"这条规则是因为 X 才有的"不是变更史，是**活约束的理由**。
  判据：删掉它，读者会不会重新犯这个错？会 → 留。不会 → 那它只是变更史，删。

- **否定句**：消解读者**已有期待**的否定是信息（`他没有回头`）；否定一个读者根本不知道存在的东西，
  等于凭空把它塞进读者脑子再否认（`（注意：没有灵气亲和度扣除）`）→ 删。
  判据见 AItelier `templates/novel_humanize.md` 第 9 条。

## 落到具体载体

| 载体 | 终态长什么样 |
|---|---|
| README / 设计文档 / CLAUDE.md | 系统现在怎么工作；不写"本次新增/变更" |
| prompt 模板 | 现在的规则；不写"以前要求 X，现在改成 Y" |
| 代码注释 | 这段代码现在做什么、为什么必须这样；保留"为什么不能改回去"的判例，删"改了 X" |
| 返工产物（正文/章纲/设计/图/计划） | 完整终态文件，没改动的部分照抄 |
| 状态记账 / 配置 | 终值 |
